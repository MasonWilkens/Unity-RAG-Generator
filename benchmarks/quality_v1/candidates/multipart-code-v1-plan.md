# Multipart code retrieval candidate

Scope selected from the three remaining development misses, before running
this candidate on the held-out repository: Path Creator's property replacement,
Playground's input/cooldown check, and Playground's scheduled destruction.

- For conjunctive implementation questions, select up to three complementary
  literal source chunks within a uniquely resolved declared type. Match parsed
  identifier references inside each chunk, preserving overload identities and
  separate windows of long methods. Exclude fields and declaration-only records.
- For named property mutations, inspect setter references rather than treating
  getter references as setter behavior. Respect any explicitly named owner;
  otherwise require a unique best property among the matching declarations.
- Carry source dependencies for partial declarations, competing properties, and
  event declarations used in selection. Keep physical citations and source hashes.
- Preserve exact lookups, kind filters, existing verified anchors, result limits,
  and context budgets. Ambiguity or bounded-read limits leave ordering unchanged.
- Expose matched identifiers and their source spans in ranking diagnostics;
  use those spans when choosing a literal window for a tight context budget.

This is evidence selection, not a proof of execution order or complete behavior.
String-valued dispatch such as Unity `Invoke` is not converted into a resolved
call edge. No project-specific names or question-specific synonym lists are used.
Selection scans at most 200 scoped chunks, 100 matching property chunks, 1,000
references per entity, and 7,000 records/20 million serialized characters overall.
Existing type lookup has its separate 100-record/256-alias bound. At most 64
dependency files accompany selected evidence. Large or ambiguous scopes abstain.

questions; the second adds explicit-owner regression coverage. Synthetic tests
also cover overloads, partial classes, split methods, string/comment decoys,
setter/getter separation, ambiguity, bounds, source freshness and context limits.
